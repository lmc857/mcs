# MCS 更新说明

> 当前版本：**0.14.2**
> 更新日期：2026-11-27
> 适用：Windows 服务版、Linux 手动部署、源码部署

本文记录近期已交付的功能、升级注意事项和当前边界。详细操作见
[用户使用手册](MCS-用户使用手册.pdf)、[部署与运维手册](MCS-使用手册.md)、
[API 参考](MCS-API参考.md) 和 [架构说明](MCS-架构说明.md)。

## 0.14.2：SIP 认证排查

- `register auth failed` 日志新增认证诊断字段：
  - `auth_user`
  - `auth_realm`
  - `auth_uri`
  - `request_uri`
  - `auth_algorithm`
  - `auth_qop`
  - `expected_realm`
- 系统设置新增“SIP 认证 Realm”，默认 `mcs`；
- 话机认证 Realm 与 MCS 不一致时，可直接在网页修改并对齐；
- 文档补充注册认证失败排查。

## 0.14.1：版本号显示

- 顶栏新增 `MCS · 版本号`；
- 侧边栏底部显示版本；
- 登录框显示版本；
- 总览/系统信息版本改为统一读取 `/api/v1/system/info`；
- `/api/v1/healthz` 返回版本，登录前也能显示；
- 修复本地构建未注入版本时只显示默认开发版本的问题。

## 0.14.0：监听能力、证书上传与重启提示

- 新增 SIP over TCP 监听 `sip_tcp`（可选，留空关闭）；
- 系统设置顶部新增“当前监听与能力”表：
  - SIP UDP/TCP/TLS；
  - HTTP/HTTPS；
  - RTP/RTCP 动态 UDP；
  - SRTP 模式；
  - STUN/TURN/公网 IP；
- 证书支持网页直接上传：
  - SIP TLS 证书/私钥；
  - HTTPS 证书/私钥；
  - 终端 CA；
- 证书路径默认提示按当前操作系统和数据目录生成，不再固定显示 Windows 路径；
- 保存有变化时页面顶部显示“必须重启服务器后才生效”，可立即重启或稍后；
- 配置版本升级到 `settings_version=4`，兼容旧设置和 TCP 字段。

## 0.13.1：设备密码编辑

- 设备列表新增“编辑”按钮；
- 可修改名称、区域、SIP 密码、抓拍 URL；
- 密码留空不改；
- 修改密码后 MCS 注销该设备当前注册，旧密码立即失效；
- 设备需用新密码重新注册，话机上的密码也要同步修改。

## 1. 0.13.0：WebRTC ICE / STUN / TURN

### 1.1 ICE 配置

- WebRTC 支持配置外部 STUN/TURN；
- 配置同时应用于 Pion 服务端和浏览器；
- 新增网页“系统设置”字段：STUN 地址、TURN 地址、TURN 用户名/密码、WebRTC 公网 IP；
- 新增 `GET /api/v1/webrtc/config`，把 ICE 配置下发给已登录浏览器；
- Pion `SetNAT1To1IPs` 支持服务器在 NAT 后发布公网 host candidate。

### 1.2 部署方式

STUN/TURN 使用标准服务，不需要 MCS 单独开发：

- STUN 可用公共 STUN 或 coturn；
- TURN 推荐 coturn，需要公网 IP、3478 UDP/TCP、中继端口范围；
- MCS 不内置 TURN 服务，只作为 ICE 客户端；
- 浏览器和 MCS 都需要能访问 TURN。

### 1.3 限制

- SIP 话机侧仍不支持 ICE/STUN/TURN；
- 未配置 TURN 时跨公网仍可能失败；
- TURN 密码会下发给登录后的浏览器，建议使用专用账号；
- 内置 TURN 服务未实现。

## 2. 0.12.0：激活码一机一码

### 2.1 机器绑定

- MCS 启动时生成本机机器码，显示在“配置 → 授权管理”；
- 机器码由系统唯一标识（Windows MachineGuid/BIOS/系统盘序列，Linux machine-id/DMI UUID，macOS IOPlatformUUID）做 SHA-256 后生成；
- 原始硬件标识不上传，只显示摘要；
- 激活码必须包含机器码，激活时与本机机器码比对；
- 机器码不一致直接拒绝；
- 旧版未绑定机器的通用激活码不再可用。

### 2.2 签发工具

`mcs-license` 新增必填参数：

```bash
-machine "MCS-C6IR-UGIW-XQ6S-TR7V-7FBQ-562V-QU"
```

客户流程：

1. 授权页复制本机机器码；
2. 把机器码、客户名称、话机数量发给供应商；
3. 供应商生成绑定码；
4. 客户粘贴激活。

### 2.3 升级兼容

0.11.0 及以前的激活码没有机器字段，升级到 0.12.0 后会被拒绝：

```text
该激活码是旧版通用授权，未绑定设备；请使用本机机器码重新签发
```

已有设备、授权到期时间等数据不会丢失；需要重新签发并激活。

### 2.4 更换硬件

重装系统、更换系统盘、虚拟机克隆/迁移、Windows sysprep 等可能导致机器码变化。机器码变化后需要按新机器码重新签发。

## 3. 0.11.0：SIP TLS 全链路与网页 TLS/SRTP 配置


### 3.1 SIP TLS

- 支持 SIP over TLS 入站监听，最低 TLS 1.2；
- **支持 MCS 出站 B 腿使用 TLS**；
- 保留终端 Contact 中的 `transport=tls`；
- 保存 REGISTER 时记录的传输方式，Contact 缺少 transport 时自动补齐；
- 报警呼叫、广播 INVITE、心跳 OPTIONS 均按终端注册传输方式出站；
- 新增 `tls_ca`，用于信任终端自签证书/私有 CA；
- 新增 `tls_insecure`，仅用于内网自签证书测试；
- 证书和私钥在网页保存时做匹配校验。

### 3.2 HTTPS 控制台

- HTTPS 监听和证书可网页配置；
- HTTPS 证书为空时复用 SIP TLS 证书；
- HTTPS 下控制台 Cookie 自动带 `Secure`。

### 3.3 SRTP 策略

新增 `srtp_mode`：

| 值 | 行为 |
| --- | --- |
| `auto` | 默认；终端协商 SAVP 就使用 SRTP，普通 RTP 也可用 |
| `required` | 点对点/报警呼叫必须使用 SDES-SRTP |
| `off` | 拒绝 SRTP，只允许普通 RTP |

仍只支持：

- SDES-SRTP；
- `AES_CM_128_HMAC_SHA1_80`；
- `AES_CM_128_HMAC_SHA1_32`；
- 音频/视频/SRTCP；
- 两腿独立密钥。

### 3.4 网页配置

位置：

```text
配置 → 系统设置 → 服务器设置
```

可配置：

- SIP TLS 监听；
- TLS 证书/私钥；
- 终端 CA；
- 跳过终端证书校验；
- HTTPS 监听；
- HTTPS 证书/私钥；
- SRTP 模式。

保存后重启生效，不需要直接修改 `config.yaml`。

### 3.5 配置兼容

- 旧版 `server_settings` 没有 TLS 字段，升级时会保留 `config.yaml` 中已有的 TLS 配置；
- 新保存的设置带 `settings_version=2`；
- 旧版没有 `srtp_mode` 时默认为 `auto`。

## 4. 0.10.0：广播分区网页管理、Windows 重启修复

### 4.1 网页广播分区

位置：

```text
业务 → 广播 → 广播分区管理
```

支持新增/修改/删除：

- 分区 ID、名称、寻呼短号；
- PCMU/Opus；
- 单播/组播；
- 组播地址端口；
- 成员分机。

配置保存到 SQLite，立即生效，重启保留。分区正在广播时禁止修改/删除。

### 4.2 Windows 网页重启

- 安装脚本增加 `sc failureflag MCS 1`；
- `-service` 模式退出前启动辅助进程，等待后执行 `sc.exe start MCS`；
- 解决部分环境开启心跳后网页重启不恢复的问题；
- 已有安装建议运行 `Repair-Service.cmd` 更新服务恢复策略。

### 4.3 会议视频发言人选择

- 不再因为静音包/舒适噪声/DTX 抢占视频；
- 按音频 RMS 能量选择发言人；
- 新发言人持续约 900ms 才接管画面；
- 静音参会者不能成为当前视频源；
- 减少画面跳到错误人员和闪烁。

### 4.4 视频查看噪音

- 网页“视频”改为纯查看，不打开浏览器麦克风；
- 只有门口机通话显示“视频对讲”，才启用麦克风；
- 服务端不再把非门口机通话的浏览器麦克风转发给 A 腿；
- 修复 1002 呼叫 8000、1003 接听后，网页看视频导致 1002 听到环境噪音的问题。

### 5.1 离线授权

- 已在线话机不强制下线；
- 新增按到期时间签发的命令参数。

### 5.3 会议视频与网页音频

- 会议视频按当前发言人切换；

- 区分“视频”和“视频对讲”。

## 6. 升级前准备

1. 备份：

```text
data/mcs.db
data/recordings/
config.yaml
.license/ 或备份的授权私钥
```

2. 记录当前版本和 Windows 服务安装方式；
3. 确认 `advertise` 使用设备可达 IP；
4. 如果启用 TLS/SRTP，准备 PEM 证书和私钥；
5. 在测试机先验证：

- 注册；
- 呼叫；
- 报警；
- 广播/寻呼；
- 视频；
- TLS/SRTP。

## 7. Windows 升级

使用新安装包或替换 `mcs.exe` 后：

```powershell
Restart-Service MCS
```

如果网页重启异常，运行安装目录下的：

```text
Repair-Service.cmd
```

0.10.0 起服务恢复策略应包含：

```powershell
sc.exe failureflag MCS 1
```

## 8. Linux 升级

```bash
systemctl stop mcs
# 备份旧二进制
cp mcs mcs.bak
# 替换新二进制和网页资源
systemctl start mcs
```

如果使用 HTTPS/TLS，确认证书路径对运行用户可读。

## 10. 当前边界

- SIP 终端只支持 SDES-SRTP，不支持 DTLS-SRTP；
- 不支持 mTLS/客户端证书认证；
- 广播、寻呼、会议仍使用明文 RTP；
- 网页配置证书填写服务器文件路径，暂不支持网页上传证书文件；
- 组播代码已实现，真实交换机和音箱仍需现场验证；
- 报警视频仍是单路当前发言人，不是多画面 MCU；
- Windows 网页重启依赖服务管理器/辅助进程，手动运行 `mcs.exe` 不会自动重启；
- STUN/TURN 使用外部标准服务，不内置 TURN；SIP 侧不支持 ICE。
