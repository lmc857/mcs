## 0. 一页摘要

**MCS 要解决的不是"打电话"，而是三件事：报警有人接、对讲看得见、广播找得到人。**

1. **垂直优先**：1.0 只做报警、对讲、广播、调度台、设备管理五大块，不做 IVR、语音信箱、队列、计费、传真等通用 PBX 功能。通用 PBX 能力放进 2.0「PBX 扩展包」。
2. **Web 优先**：管理端和调度台都用浏览器，调度员通过 WebRTC 直接接听/呼叫/广播，不需要装桌面客户端（ZYCOO 的调度台是桌面 App，这是我们的差异点）。
3. **单机优先**：1.0 不做集群、多租户、双机热备，把 500 路单机做稳；HA 和集群放 2.0。
4. **交付优先**：单文件 + 安装包 + 离线许可，客户现场零依赖；报警/广播/对讲都要能"装完当天用起来"。
5. **可集成**：OpenAPI + Webhook/MQTT，向上对接现有报警平台（alarmserver-go），向下对接设备配置工具（sip_web）。

**1.0 验收口径**：500 台设备注册、250 路并发通话、500 个广播终端、16 路视频对讲；一键报警从按键到调度台弹屏 P95 ≤ 500ms；72 小时 80% 负载稳定。

## 1. 定位与边界

### 1.1 产品是什么

MCS 是一台部署在客户内网或云上的通信服务器：

- 让报警设备（一键报警柱、报警箱、手环、烟感网关等）注册进来，按键即呼叫值班室；
- 让门口机、对讲终端与值班室/住户双向音视频通话，并远程开锁；
- 让 SIP 音箱、广播网关按分区播放实时语音、TTS、音乐、定时打铃和紧急广播；
- 给值班员一个 Web 调度台：设备状态、地图、报警弹窗、一键操作、录音回放；
- 给管理员一个 Web 管理后台：设备、账号、分区、策略、话单、许可、诊断。

### 1.2 1.0 不做什么

| 不做 | 原因 | 去向 |
| --- | --- | --- |
| 通用企业 PBX 全套（IVR、语音信箱、队列、会议、BLF、IM） | 与垂直场景无关，拖长周期 | 2.0 PBX 扩展包 |
| 集群 / 多租户 / 双机热备 | 500 路单机足够，先保交付 | 2.0 |
| 计费、运营商对接、传真 | 非目标客户 | 不做 |
| 桌面客户端 / 手机 App | 浏览器 WebRTC 覆盖 90% 场景 | 2.0 视需求 |
| 自研/离线 TTS 引擎 | 1.0 用在线 TTS，离线放后期 | 2.0 视客户网络条件 |

### 1.3 与通用 PBX、ZYCOO 的差异

| 维度 | 通用 PBX（miniSIPServer 等） | ZYCOO IP Audio | MCS |
| --- | --- | --- | --- |
| 核心场景 | 企业分机、外线、总机 | 广播 + 调度 | 报警 + 对讲 + 广播 |
| 报警处置 | 无（只是一通电话） | 有告警，但偏广播 | 事件生命周期 + 升级链 + 录证 + 平台联动 |
| 调度台 | 无 / 简单 | 桌面客户端 | 纯 Web + WebRTC |
| 部署 | Windows/Linux | Linux 镜像 / 一体机 | Windows/Linux/macOS/Docker，单文件 |
| 设备接入 | 标准 SIP | 自有生态 | 标准 SIP + 自家报警设备 + 自动配置 |
| 平台对接 | 弱 | 封闭 | OpenAPI / Webhook / MQTT |

### 1.4 已确认的关键前提（2026-11-16）

| 项 | 确认结论 | 对方案的影响 |
| --- | --- | --- |
| 设备来源 | 报警设备、门口机、SIP 音箱**均为自研** | 可统一 SIP 行为与固件；型号模板可标准化；兼容风险大幅下降，但要管住固件版本碎片化 |
| 广播终端 | 支持**标准 SIP 自动应答**，**必须支持组播** | 组播列为 P0；大区默认组播、小区单播兜底 |
| 视频 | 门口机为**标准 H.264/SIP** | 透传即可，不做转码；调度台 WebRTC 观看 |
| TTS | **本机 Kokoro-82M（Apache-2.0），OpenAI 兼容接口** | 1.0 只做在线 TTS + 缓存；中文 `zf_001`、英文 `af_heart`，24k WAV 重采样到 8k |
| 平台 | 需要 **Windows + Linux**，**首发 Linux** | Linux 为 1.0 首发平台；Windows 同代码紧随（M5 后 4 周内） |

> 自研设备是最大优势：可以把"报警触发头、自动应答头、组播加入/退出、开锁指令、快照接口、固件版本上报"固化成 MCS 设备协议，不再被第三方兼容性拖住。协议约定见技术方案第 8.7 节。

## 2. 用户与场景

### 2.1 目标客户

| 客户类型 | 典型规模 | 核心诉求 |
| --- | --- | --- |
| 报警运营服务商 | 多站点，每站 50~500 设备 | 报警必达、可升级、可取证、能对接平台 |
| 园区 / 物业 | 100~500 设备 | 门口机对讲、保安巡逻、背景音乐、紧急广播 |
| 学校 / 医院 | 100~500 终端 | 打铃、通知、一键报警、分区广播 |
| 工地 / 管廊 / 变电站 | 50~200 终端 | 一键报警、广播、无人值守 |
| 系统集成商 | 项目制 | 好部署、好对接、好维护、可白标 |

### 2.2 用户角色

| 角色 | 在哪用 | 主要动作 |
| --- | --- | --- |
| 超级管理员 | Web 管理 | 全部配置、许可、升级 |
| 系统管理员 | Web 管理 | 设备、分区、策略、用户 |
| 调度员 | 调度台 | 接报警、对讲、广播、查录音 |
| 值班员 | 调度台（受限） | 接听本区域报警/对讲 |
| 维护员 | Web 管理 | 设备状态、日志、诊断 |
| 审计员 | Web 管理 | 只读话单、录音、审计日志 |
| 大屏 | 只读 | 设备状态、报警滚动 |

### 2.3 六个典型场景

**S1 一键报警（核心）**
老人/路人按下报警柱按钮 → 调度台 1 秒内弹屏（设备、位置、地图、周边摄像头、历史报警）→ 值班员接听，双向语音，自动录音 → 20 秒无人接自动升级到班长/保安队长，40 秒升级到外部电话/短信 → 处置完成后填写结果、关闭事件 → 全程留痕，可导出证据包。

**S2 视频对讲 + 开锁**
访客按门口机 → 值班室调度台振铃并显示视频 → 值班员接听、双向对讲 → 确认后点击"开锁"，服务器向门口机发送开锁指令 → 记录访客、抓拍、录音；无人接听 20 秒转保安手机。

**S3 紧急广播**
校长/值班长在调度台点"紧急广播"→ 选全校或某分区 → 正在播放的背景音乐/定时广播立即被抢占 → 500 个音箱分批接入，状态实时可见 → 讲话结束，恢复背景音乐 → 全程记录操作人、分区、时长。

**S4 定时广播/打铃**
管理员配置一周计划：7:30 起床号、8:00 上课铃、12:00 午间音乐、17:00 放学铃；节假日自动跳过；临时任务可一键插播；冲突时按优先级执行。

**S5 设备接入**
管理员选型号模板 → 批量导入 MAC/编号 → 系统自动生成 SIP 账号 → 通过配置 URL 或 `sip_web` 下发到设备 → 设备注册上线 → 绑定摄像头/分区 → 一键测试呼叫。

**S6 多区域/多值班室**
园区分 A/B/C 区，每区一个值班组；报警按区域路由到对应值班室；夜间无人值守时统一转总值班室；紧急广播可跨区全呼。

## 3. 版本与容量分级

### 3.1 授权版本

| 版本 | 注册设备 | 并发通话 | 广播终端 | 视频通话 | 典型场景 |
| --- | --- | --- | --- | --- | --- |
| **MCS-50** | 50 | 25 | 50 | 4 | 门店、小型园区 |
| **MCS-100** | 100 | 50 | 100 | 8 | 小区、小学 |
| **MCS-200** | 200 | 100 | 200 | 12 | 中型园区、医院 |
| **MCS-500** | 500 | 250 | 500 | 16 | 大型园区、多校片区 |

> 1.0 功能一致，仅容量不同——降低销售与交付复杂度。视频路数单独限制，因为占用带宽与转发资源更多。

### 3.2 授权与超限策略

- **授权文件**：Ed25519 签名，绑定机器指纹（CPU/主板/网卡组合），离线激活；含版本、设备数、并发数、广播终端数、视频路数、到期时间。
- **试用**：30 天全功能（按 MCS-500 放开），到期转受限模式（保留配置与录音，不能新增设备或发起新呼叫）。
- **超限行为**：
  - 达到 80%：管理端横幅提醒 + 事件日志；
  - 达到 100%：新设备注册返回 `403`，新呼叫返回 `486 Busy`，已有通话不受影响；
  - 广播终端超限：任务启动前校验，拒绝并提示升级。
- **升级**：导入更高版本 license 立即生效，无需重启；降级需先删设备。
- **防篡改**：license 签名校验、系统时间回拨检测、关键计数内存+落盘双校验。

### 3.3 容量规划（单机）

| 指标 | MCS-500 目标 |
| --- | --- |
| 注册设备 | 500（含话机、门口机、报警柱、音箱、网关） |
| 并发通话 | 250 路（G.711 中继） |
| 广播终端 | 500 个（授权总量）；最多 4 个并发任务（不同分区） |
| 视频通话 | 16 路（H.264 透传） |
| 报警事件 | 60 次/分钟（峰值），持续 10 分钟 |
| 注册风暴 | 50 次/秒，持续 10 秒 |
| 录音 | 默认 90 天，可按分区/设备配置 |

## 4. 功能架构

```text
MCS
├─ A 设备与接入      型号模板 · SIP 账号 · 自动配置 · 注册状态 · 分组/区域 · 摄像头 · 中继
├─ B 报警            策略 · 值班组 · 振铃/升级链 · 弹屏 · 处置 · 录音 · 通知 · 统计 · 演练
├─ C 对讲            门口机呼叫 · 视频 · 开锁 · 转手机 · 访客 · 抓拍 · 多值班室
├─ D 广播            分区 · 优先级 · 实时寻呼 · 紧急广播 · 定时/打铃 · TTS · 音乐 · 联动
├─ E 调度台          WebRTC · 状态墙 · 地图 · 报警队列 · 一键操作 · 多路视频 · 预案
├─ F 通话与媒体      呼叫/中继/拨号 · 前转/保持/转接 · 录音 · 话单 · DTMF · TLS/SRTP
└─ G 平台            Web/RBAC · 多语言 · 许可 · 监控 · 日志 · 备份 · 诊断 · 升级 · OpenAPI
```

**模块边界**：

- A 负责"设备能进来、配置能下去、状态看得见"；
- B/C/D 是三个业务域，共用 F 的呼叫与媒体能力；
- E 是操作员工位，不承载业务逻辑，只做展示与指令；
- G 是横切能力，所有模块通过统一事件总线交互。

## 6. 关键业务流程

### 6.1 一键报警（含升级链）

```text
设备                 MCS                      值班员A        值班员B
 │ REGISTER ─────────▶│                         │              │
 │◀─────── 200 OK ────│                         │              │
 │ INVITE 8000 ──────▶│ 查策略/值班表            │              │
 │◀── 100 Trying ─────│                         │              │
 │                    │ INVITE ────────────────▶│              │
 │                    │ INVITE ───────────────────────────────▶│
 │◀── 180 Ringing ────│                         │              │
 │                    │ WS alarm.created ──────▶│              │
 │                    │◀───────────── 200 OK ───│（先接听）      │
 │◀── 200 OK ─────────│ CANCEL 另一方            │              │
 │◀════ RTP 双向语音 + 录音 ═══════════════════▶│              │
 │ BYE ──────────────▶│ 写 CDR/录音/时间线        │              │
```


要点：

1. 报警呼叫**不排队**，直接按策略 fork 到值班组；无人接才升级。
2. 设备侧先听到"报警已受理，请稍候"提示音（可配），避免重复按键。
3. 弹屏与呼叫并行，不依赖值班员接听；未接也要留下事件；同时通过 Webhook 推送报警平台。
4. 事件关闭必须填写处置结果（可配"误报"快捷原因），形成闭环。

### 6.2 视频对讲 + 开锁

1. 门口机呼叫 `6001`（值班组短号），SDP 带 H.264 视频。
2. 调度台振铃，先显示抓拍图，接听后显示实时视频。
3. 值班员点"开锁"→ MCS 按型号模板发 DTMF/INFO/HTTP → 门口机动作 → 返回结果。
4. 开锁前后抓拍、录音、访客记录绑定同一事件。
5. 20 秒无人接 → 转保安手机；仍无人接 → 留言/短信（2.0）。

### 6.3 紧急广播（优先级抢占）

1. 调度台点"紧急广播"→ 选分区 → 二次确认（可关）。
2. 广播引擎检查权限与优先级：`P0 紧急 > P1 报警 > P2 实时 > P3 定时 > P4 背景音乐`。
3. 抢占低优先级会话：停止当前任务、记录被抢占任务、保留恢复点。
4. 向终端批量发 INVITE（自动应答头），终端接入后加入 RTP 组播/单播。
5. 操作员讲话（WebRTC 麦克风）→ 服务器混音/编码 → 扇出；UI 实时显示成功/失败终端。
6. 结束 → BYE → 恢复被抢占的背景音乐（可配）。

### 6.4 定时广播/打铃

- 任务类型：立即、周计划、节假日、拨号触发、一键触发。
- 冲突处理：同分区同时刻多个任务，按优先级执行；低优先级顺延或丢弃（策略可配）。
- 失败处理：终端离线跳过并记录；任务整体成功率低于阈值时告警。
- 支持"临时插播"：立即任务可覆盖当天计划。

### 6.5 设备接入与自动配置

1. 管理端选型号模板 → 导入 MAC/编号 → 生成 SIP 账号（分机号可规则生成）。
2. 配置下发二选一：
   - **配置 URL**：设备启动请求 `http://mcs/provision/{mac}.cfg`，MCS 按模板渲染；
   - **`sip_web` 对接**：MCS 调用 `sip_web` 现有接口写入 SIP 参数（复用现场流程）。
3. 设备注册 → 绑定区域/摄像头 → 测试呼叫 → 上线。
4. 离线超过阈值 → 事件 + 通知；恢复后自动清除。

### 7.3 设计原则

- **大按钮、少层级**：值班员在 3 秒内完成接听/广播/开锁。
- **声光提示**：报警用不同音色 + 闪烁 + 标题栏提醒，可调音量。
- **一屏原则**：报警弹屏不跳页，地图与视频同屏。
- **断线可恢复**：WebSocket 重连后拉取快照，不丢状态。
- **权限可见**：无权限的按钮置灰并提示原因。
- **浏览器要求**：Chrome/Edge 最近两个大版本；必须 HTTPS（WebRTC 安全上下文）。

### 11.3 预算

- 人力 30~36 人月 × 3~4 万 ≈ **90~144 万**；
- 测试设备/证书/缓冲 ≈ **30~40 万**；
- 合计约 **120~180 万**（不含市场、差旅、认证）。

### 11.4 验收与试点

- **功能验收**：第 5 节 P0/P1 全部通过，P0 缺陷为零。
- **性能验收**：第 9 节指标全部达标，报告归档。
- **安全验收**：SIP 扫描、Web 扫描、弱口令、越权、盗打测试通过。
- **试点**：2 家客户（1 个园区 + 1 个学校/报警运营），连续运行 30 天，收集问题清单。
- **交付验收**：安装包、许可、文档、培训、诊断包齐全，客户可独立完成日常操作。

## 13. 已确认与待确认

### 13.1 已确认（2026-11-16）

- 设备全部自研，可统一固件与 SIP 行为；
- 广播终端支持标准 SIP 自动应答，必须支持组播；
- 门口机视频为标准 H.264/SIP；
- TTS 使用在线服务；
- 平台需 Windows + Linux，首发 Linux。

### 13.2 仍需确认

1. **设备型号清单**：报警柱/报警箱/门口机/SIP 音箱的具体型号与固件版本，用于建型号模板与兼容矩阵。
2. **TTS 供应商与音色**：阿里云/腾讯云/Azure？是否需要多音色、方言、语速控制？
3. **地图来源**：客户平面图上传即可，还是需要在线/离线地图？
4. **合规要求**：项目是否要求等保、3C、入网许可、日志留存审计？
5. **Windows 发布窗口**：M5 后 4 周内是否可接受？

## 14. M0 两周启动清单

目标：用真实设备验证"注册 → 呼叫 → 报警弹屏 → 录音 → Web 壳"，并产出三平台二进制；不追求功能完整。

| 天 | 后端 | 前端 | 当日产出 |
| --- | --- | --- | --- |
| D1~D2 | 仓库骨架、CLI、配置加载、SQLite 迁移、日志 | Vue 壳、登录页、路由框架 | `mcs` 可启动，浏览器能登录 |
| D3~D4 | 注册/鉴权/位置服务、OPTIONS 保活、设备列表 API | 设备列表/状态页（真实数据） | 软电话注册成功，页面可见 |
| D5~D6 | B2BUA 基本呼叫、报警短号路由、RTP 中继 | 调度台通话条、来电弹窗 | 两台终端互通语音 |
| D7 | 报警事件落库、WebSocket 推送、录音落盘 | 报警弹屏、录音列表 | 按键 → 弹屏 → 接听 → 录音 |
| D8 | CDR、录音回放 API、配置导入 | 话单/录音回放页 | 通话结束可查可听 |
| D9 | 真实报警设备接入、NAT/保活修正 | 设备详情/地图占位 | 设备端到端跑通 |
| D10 | Windows/Linux/macOS 交叉编译、安装包雏形 | 演示脚本 | 三平台产物 + 演示 + 复盘 |

**M0 验收**：

1. 1 台真实报警设备 + 2 款软电话同时在线；
2. 设备按键到调度台弹屏 ≤ 1s，接听后双向语音清晰；
3. 通话自动录音，Web 可回放，话单含主叫/被叫/时长/结果；
4. Windows、Linux、macOS 各一个可运行产物；
5. 拔网线 30s 再插回，设备 60s 内恢复注册。

**M0 风险点**：设备 SIP 行为、NAT 单通、浏览器 WebRTC 权限。D9 前必须拿到真实设备；拿不到则用 sipp + 软电话替代，并在 M1 补设备联调。
